# 内外网服务与网络管理

## 企业方案参考

[微软 Split-brain DNS 架构](https://learn.microsoft.com/en-us/azure/architecture/example-scenario/networking/split-brain-dns)使用 DNS 区分企业内外网入口。对于可管理 DNS 的环境，同一域名在内网解析到内网网关，在外网解析到公网入口，可以避免应用自行猜测用户网络。

当前环境含有独立公网域名、内网主机名及路径穿透，因此门户采用双地址目录作为过渡方案。网络管理仅维护登记信息与选址规则，不修改真实 DNS、代理、路由、防火墙或证书。

## 默认选址

1. 浏览器手动选择“内网优先”或“外网优先”时使用该选择，保存在当前站点的 localStorage，不保存管理员令牌。
2. 自动模式优先匹配网络管理中的外网/内网门户主机规则。规则为精确主机名，不含协议、端口、路径或通配符。
3. 私有 IPv4、IPv6 ULA/link-local、loopback、localhost、.local 判为内网入口。其余入口默认外网。
4. 判断的是访问门户的主机名，不是浏览器的真实客户端 IP。通过公网域名访问时，即使人在局域网，也默认外网；可手动切换。不要用未经信任的 X-Forwarded-For 或主动探测私网来猜测客户端网络。
5. 同一域名配分视 DNS 时，浏览器无法仅从域名知道解析到哪个网络。推荐使用同一服务 URL 交由 DNS 选路，或使用内外网不同的门户主机名；本版本不声称能识别同域名的 DNS 答案。
6. 当前网络缺少地址时显示未配置，不静默跨网络回退。卡片仍分别提供已配置的内外网快捷链接。

## 服务与数据兼容

Service 新增 `internalUrl`、`externalUrl`、`networkId`。旧 `url` 按历史使用方式迁移为外网地址，并作为旧客户端兼容字段保留。现有 ID、租户归属、部署、操作记录保持不变。

`PUT /api/services/{id}` 编辑服务及双地址，保留记录 ID 和运行状态。服务状态不因为 URL 已配置就变成健康；内网地址从清单登记后仍需实际网络、DNS、TLS 和服务认证验证。

`PUT /api/network-settings` 保存门户主机规则及网络区域。配置含 revision，过期的修改返回 409，避免覆盖他人的配置。已关联服务的网络不能直接删除。网段必须为有效 CIDR；未确认的网段或 DNS 应留空，不根据单个 IP 猜测网络掩码。

## 使用步骤

1. 输入管理员令牌后打开“网络管理”，登记内网、外网、穿透/VPN 等网络区域。
2. 在“服务资源 → 编辑”或网络管理的“配置地址”中分别维护内外网 URL，并关联资源所在网络。
3. 在网络管理中登记访问门户本身的内外网主机名。
4. 用不同入口访问门户，确认自动模式选址；也可在顶部切换访问方式。

内网域名需要客户端 DNS/hosts 可解析，客户端需信任私有 CA，网络本身必须可达。目录切换不构成权限隔离，公网界面不会让私网服务自动变成公网服务。
